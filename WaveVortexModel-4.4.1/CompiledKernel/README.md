# Prepared spectral execution

The v4 constant-stratification kernel prepares its FFT plans, scratch arenas and coefficient executor at construction. A workspace permits one synchronous active call. The default coefficient execution uses the calling thread and one persistent background thread; `WV_KERNEL_COEFFICIENT_WORKERS=1` selects serial execution. Every coefficient stage completes before FFT execution begins. Construction joins any workers already launched if a later launch fails, and destruction joins the retained workers.

The default compact constant schedule has seventeen logical prepared operation slots and a `4C+6R` numerical scratch bound. Here `C=Nz*Nkl` complex values, `H=(floor(Nx/2)+1)*Ny*Nz` complex values in a full horizontal half-spectrum, and `R=Nx*Ny*Nz` real spatial values. Logical slots are distinct from native FFTW handles. Call `prepareScalarAdvection()` during setup when scalar advection is configured. Preparation is idempotent and can be retried after setup failure. The portable integration system already does this for its configured tracers. Ordinary RHS, RHS that returns velocity, and RHS that consumes prepared velocity retain their existing interfaces and shared particle/tracer velocity behavior.

Issue [#358](https://github.com/JeffreyEarly/wave-vortex-model/issues/358) implemented the compact constant schedule, now selected by default in new builds. `WV_KERNEL_COMPACT_CONSTANT_CANDIDATE=OFF` or explicit frozen C++ execution options retain the original schedule for comparison. Existing CMake caches keep their previous setting; use a fresh build directory or explicitly select `ON` to adopt the new default. Its identity is `retained-compact-streamed-target-three-channel-v1`. It assembles directly into four retained complex volumes, executes retained-row DCT-I/DST-I transforms, and projects directly into canonical `[Nj,Nkl]` outputs. Its base numerical arena is `4C+6R`, where `C=Nz*Nkl` complex values. Kernel contract 4, source API v1 and checkpoint layouts retain their scientific meanings; the execution schedule has separate version 1 metadata.

The [large-grid adoption decision](../.github/ci-evidence/issue-455-large-grid-adoption/README.md) passes scientific, timing and memory gates at 256×256×129 and 512×512×257. Native and MATLAB-loaded complete flux take approximately 49% and 48% of frozen-control time; six short integration profiles take approximately 44% geometrically. These are measurements on the recorded M4 Max host and worker policy. The owner accepts the previously measured 18.6–20.7% slowdown at 32×24×33; small-grid optimization is not planned. The [original decision](../.github/ci-evidence/issue-358-adoption/README.md) remains historical evidence under its original timing gate.

The compact schedule prepares stage workers at setup: horizontal outer workers 12 with one internal FFTW worker, Type-I workers from the requested provider policy, coefficient workers 2 and pointwise workers 12. Pointwise stages dispatch serially below 4096 real elements. Explicit C++ options and CMake settings support qualification on other hosts. No process-wide BLAS setting is changed. Worker screening is evidence for the recorded host; it is not a cross-platform performance guarantee. The [adoption harness](../Benchmarks/constant-adoption/README.md) and [large-grid protocol](../.github/planning/issue-455-large-grid-qualification.md) record the control and acceptance rules.

Configured scalar calculus uses `max(4C,H)+6R`: it borrows the idle first three real volumes for an immutable full-grid scalar spectrum and streams three derivative inverses through one working spectrum into the final three real volumes. It preserves arbitrary resolved scalar modes outside the retained WV set and leaves caller input and velocity buffers unchanged.

MEX estimates distinguish the base arena from configured scalar storage. Constructed metrics include known provider, shared horizontal, executor and management storage, counting shared resources once per kernel. Actual FFTW handle counts are module-global lifecycle metrics; native plan internals and thread storage remain opaque. Existing validated MEX binaries remain valid, and capabilities report metadata from the installed binary rather than inferring its schedule from newer source defaults.

The constant-stratification tracer operator differentiates horizontally at every grid depth. Its vertical derivative projects onto the retained `Nj` cosine modes before differentiation, matching MATLAB `diffZF`; omitted vertical modes contribute no vertical derivative. Optional tracer antialiasing remains a separate horizontal projection.

Successful prepared native execution performs no application C++ allocations or thread launches. This covers forward/inverse transforms, F/G derivatives, the three RHS forms, and scalar advection with and without antialiasing. Failure reporting can allocate diagnostic strings. The reference FFT provider still allocates for vertical real-to-real execution. Its horizontal real/complex execution is allocation-free after preparation.

## Native FFTW ownership

`destroysInput=false` requires preservation for out-of-place execution. Native r2c and out-of-place DCT-I/DST-I plans request `FFTW_PRESERVE_INPUT`. Multidimensional c2r has no preserving algorithm in FFTW, so setup returns `unsupportedOperation`; callers must explicitly prepare destructive scratch and set `destroysInput=true`. The existing production inverse paths already use that scratch. No hidden preservation copy is retained.

In-place execution inherently overwrites shared storage and requires identical input/output pointers. This adapter supports in-place vertical real-to-real transforms with matching strides. Padded in-place horizontal transforms are rejected during setup. Out-of-place execution rejects identical pointers and partially overlapping addressed spans before entering FFTW. Positive strides, supported ranks, span arithmetic and declared buffer capacities are checked during setup. A failed setup leaves any existing output plan unchanged.

Planning buffers and raw plans have RAII ownership immediately after acquisition. All plan destruction, including cleanup after a wrapper allocation failure, takes the same mutex as planning. Lifetime plan counters include raw plans, so partial construction is visible and must balance.

These choices follow FFTW's [planner flags](https://www.fftw.org/fftw3_doc/Planner-Flags.html) and [thread safety](https://www.fftw.org/fftw3_doc/Thread-safety.html) contracts.

## Storage accounting

`kernelManagementBytes` includes the executor object and its retained `std::thread` vector capacity. Descriptor storage, scratch capacity, engine storage and plan wrapper storage remain separately reported. `persistentBytes` sums the known retained C++ storage. FFTW's internal plan storage and the thread runtime's heap bookkeeping, stacks and operating-system resources are opaque; these totals are lower bounds, not RSS or a complete process-memory bound. The native allocation test counts application `new`/`new[]`, including aligned allocation, and does not interpose FFTW/libc internal allocation.

## Prepared retained-horizontal and matrix services

`WaveVortexKernel/WVSpectralOperators.hpp` defines internal contract `wave-vortex-spectral-operators-v1`. It is additive to kernel contract 4 and portable extension source API v1. The kernels retain canonical interleaved coefficients. Constant stratification uses the compact schedule described above; variable stratification retains its existing prepared-matrix execution. These services establish the boundary used by the hydrostatic implementation in issue #295 and constant schedule adoption in #358; they do not decode modal checkpoint records or enable additional MATLAB preview transforms.

Create an immutable operator with `create(specification, provider, result)`, then call `createWorkspace(workspace)` during setup. A failed construction leaves the previous result unchanged. Operators copy scientific values and exact identities; callers may release their source arrays after successful preparation. Workspaces retain the operator's immutable dependencies and can outlive its handle. Rebuild the operator and create new workspaces when geometry, stratification, retained basis, normalization, source matrices, mode membership or layout changes. Ordinary state/time updates only change execution inputs. A workspace from another preparation is rejected even if its dimensions match.

Each workspace permits one synchronous active call and rejects reentry. The default full-FFT workspaces own independent resources. Native pruned workspaces prepared through a shared engine may share compatible worker pools, plans and staging storage; simultaneous calls using the same shared resources return `reentrantExecution`. Separate engines provide independent execution. Workspace creation is a setup operation and must be serialized if the provider requires it. Pruned application workers are prepared during setup and joined at destruction. Vendor BLAS may manage its own opaque resources; the Accelerate adapter does not change process-wide threading settings.

### Horizontal mapping and normalization

`WVRetainedHorizontalSpecification` contains the real `[Nx,Ny,planes]` grid, positive domain lengths, the complex `[planes,Nretained]` layout and the exact ordered signed `(k,l)` keys. `planes` may be a truncated vertical extent and does not imply the physical `Nz`. The real and retained family names must match. `modeSet` names the supplied ordered set; it is the caller's responsibility to associate the correct identity with that set. No radius rule or approximate grouping substitutes for the explicit keys.

Supply one representative per retained Hermitian orbit. Signed keys lie within `[-floor(N/2),floor(N/2)]`; aliases such as the two signs of an even-grid Nyquist index, repeated keys and both members of a conjugate pair are rejected. Arbitrary retained order and negative representatives are supported. Forward execution performs the full provider FFT and gathers that order. Inverse execution zeroes omitted modes, embeds retained values, completes boundary conjugates and runs the full inverse. DC and self-conjugate Nyquist coefficients must have exactly zero imaginary part on inverse input; forward output sets those imaginary parts to zero.

For `N = Nx*Ny`, normalization scales the provider's unnormalized forward and inverse transforms as follows. All three conventions recover retained coefficients after synthesis and analysis; synthesis discards modes outside the retained set.

| Convention | Forward scale | Inverse scale |
| --- | --- | --- |
| `forwardUnit` (WVM default) | `1/N` | `1` |
| `unitary` | `1/sqrt(N)` | `1/sqrt(N)` |
| `inverseUnit` | `1` | `1/N` |

The default workspace owns a dense real grid and a full horizontal half-spectrum, plus forward and inverse plans. Only disposable scratch is passed to destructive c2r. Caller inputs and output padding remain unchanged. Validation failures occur before caller output is written; a provider execution failure may leave an already completed plane in the output. The default schedule works with the reference DFT or native FFTW adapter.

Explicit `WVRetainedHorizontalSchedule::streamingPrunedTile16` selects the optional native retained-plan capability. It executes real row FFTs and only the retained complex columns, stages tiles of sixteen planes, clears reusable inverse storage contiguously and gathers directly into the declared family view. Unsupported providers fall back to full FFT; genuine preparation failures propagate. `createShared` retains the supplied engine. Compatible native resources are weakly cached per engine, with exact geometry, active columns, retained count and effective worker count in the key. No variable-stratification kernel opts into this schedule implicitly.

`createWorkspace(workspace,false)` omits full-grid derivative preparation. The compact constant kernel uses this form to avoid a hidden full-volume arena; its full-FFT fallback streams one plane. Callers needing `spatialDerivative` use the default `true`, which preserves all resolved modes, including modes outside the retained coefficient set. A workspace without that preparation rejects the derivative operation.

### Vertical matrices and exact groups

`WVVerticalSpecification` selects reconstruction `[Nz,Nj]`, projection `[Nj,Nz]` or cross-family `[Nj,Nj]`. It supplies real matrix records with explicit action, input/output family, source identity, operator name, extents, strides and capacity. The source identity must describe the authoritative geometry, stratification, basis and normalization revision. The service validates consistency among these supplied identities; it cannot establish their scientific provenance. The future modal decoder owns that responsibility. Zero G/barotropic operators and truncated bases are valid.

Each group gives an exact group identity, matrix record index and an explicit list of retained columns. Lists may be discontiguous or reordered. Every retained column must occur exactly once, group identities must be unique and all input records must be used. Input and output share the same ordered mode-set identity and complex representation. Repeated `(source,name)` matrix identities reuse storage only after all addressed matrix values compare bit-for-bit. Different identities remain distinct even when their values are equal; conflicting values under one identity are rejected. There is no approximate deduplication or matrix expansion per Fourier mode.

Split execution prepares one real matrix per identity and applies two real matrix products. Interleaved execution prepares one complex matrix per identity with zero imaginary components and applies one complex product directly to interleaved fields. `WVCreateScalarMatrixBackend` provides independent scalar multiplication. The optional `WaveVortex::AccelerateMatrix` adapter supplies two DGEMMs or one ZGEMM; vendor headers remain outside the portable core. Set `WV_ENABLE_ACCELERATE=OFF` for the portable implementation, including non-Apple builds. Calling the disabled adapter factory returns `unsupportedOperation`.

Contiguous groups with unit row strides and valid BLAS leading dimensions use direct field views. Other valid layouts gather into prepared scratch, multiply, and scatter. Scratch capacity is bounded by the largest group requiring packing. Accumulation explicitly selects overwrite or add; overwrite does not read the previous destination. Packing preserves the selected split or interleaved representation and does not introduce hidden state-layout conversion.

### Views, ownership and accounting

All extents and element strides are positive. Complex strides count complex elements for interleaved storage and doubles for each split component. Matrix strides count doubles. Capacity is in bytes, including addressed padding; for split fields it is the minimum capacity of the two component buffers. Set only the pointers for the declared representation. Execution checks null/alignment, overflow, capacities, split-component overlap and cross-input/output overlap before mutation. Capacity declarations must truthfully describe live caller-owned allocations. Only out-of-place execution is supported.

Complex and matrix layouts reject repeated addressed elements. Real-grid layouts support permuted padded nested dimensions; unusual interleaved dimensions with overlapping bounding intervals are conservatively rejected. Alias checks also use addressed bounding spans, so sharing padding within those spans is rejected. Provider integer limits are checked before BLAS execution. A single-column view may have an unused small column stride; it is packed when that stride is not a valid BLAS leading dimension.

Successful prepared execution performs no application C++ allocation with the reference horizontal FFT, native FFTW, scalar matrix backend or Accelerate backend. Preparation and failure diagnostics may allocate. Tests count application `new`/`new[]`, not vendor `malloc` or internal worker activity.

Horizontal `persistentBytes()` reports the operator's objects, identities and mapping capacity; add `providerBytesLowerBound()` once, plus each workspace's `persistentBytes()` and `planBytesLowerBound()`. Vertical operator accounting includes its backend and prepared matrix capacity; `matrixBytes()` is the numerical-matrix subtotal, not an additional allocation. Add each vertical workspace's accounting once. Shared immutable data is not counted again per workspace. Object/vector capacities and string capacities are accounting estimates: small-string storage can already be inline, while shared-ownership control blocks, allocator overhead and vendor internals are excluded. These numbers are not RSS or an exact process-memory bound.

`TestWVSpectralOperators` checks independent long-double DFT and matrix oracles, odd/even nonsquare grids, masked/unmasked WVM retained sets, truncated bases, all normalization conventions, DC/Nyquist handling, split/interleaved direct and packed groups, accumulation, immutable preparation, identity conflicts, invalid spans/aliases, setup failures, separate concurrent workspaces and zero prepared allocations. The verification ledger is `.github/planning/issue-357-verification.md`.

## Variable-transform execution

Stratified QG, Hydrostatic and Boussinesq constructors accept an optional `WVVariableExecutionOptions` after the matrix backend factory. Defaults preserve full FFT/gather and the established nonlinear path. `horizontalSchedule=streamingPrunedTile16` requests the prepared pruned provider; `horizontalWorkers` configures its outer executor. `horizontalScheduleIdentifier()` reports the actual schedule, including `full-fft-gather` when the reference provider falls back. Scientific contracts and canonical coefficients remain unchanged.

`streamedNonlinear=true` borrows validated prepared advection fields without copying them. Hydrostatic streams physical tendencies through reusable target storage, reducing real numerical scratch from ten volumes to six. The compact Boussinesq path also uses six real volumes, preserving its four completed horizontal target spectra for final wave/balanced projection. Its exact persisted matrix groups, cross-family projection, vertical velocity and displacement/stratification term are unchanged. SQG writes an unprojected raw tendency directly into its validated caller destination.

`spectralSchedule=compactSplitFusedViews` selects internal split real/imaginary arrays and direct family views for coefficient construction, horizontal/vertical transforms and final projection. It requires the pruned horizontal schedule and streamed nonlinear option. Canonical public coefficients remain interleaved. Exact matrix groups use maximal contiguous runs in their existing order; nonunit-stride cases retain the prepared packing fallback. `pointwiseWorkers` prepares a persistent executor for independent physical-grid products. Its stages complete before horizontal or vertical work starts. Setup validates a positive worker count and accounts for executor storage; warmed calls create no workers.

The options are available through C++ kernels and explicit runtime `WVVariableKernelServices`; portable defaults retain the established scalar policy. Eligible new Apple-silicon native runner builds select the qualified compact policy automatically, using up to twelve horizontal and eight pointwise workers with one FFTW internal worker. See the [runner policy](../PortableRuntime/README.md) and [complete adoption evidence](../.github/ci-evidence/issue-455-variable-final-adoption/README.md) for selection rules and measured scope. MATLAB preview support is unchanged. Full-grid scalar derivatives preserve all resolved frequencies and Nyquist rules, with bounded derivative workspace included in the storage ledger. [The variable-transform harnesses](../Benchmarks/variable-adoption/README.md) separate direct-kernel flux from complete-model qualification. Parity dump tools accept `-pruned` and `-compact` on reference/native/native-Accelerate provider names; the MATLAB test classes exercise these configurations and add native combinations when requested.

## Stratified QG numerical kernel

`WaveVortexKernel/WVTransformStratifiedQGKernel.hpp` implements the standalone variable-stratification A0/QGPV kernel under internal contract `wave-vortex-stratified-qg-kernel-v1`. It consumes an immutable `WVStratifiedModalSource`; the runtime's `WVStratifiedModalRecord` implements that interface after validating the MATLAB file. The numerical core has no NetCDF/MATLAB dependency and does not solve an eigenproblem. This kernel does not enable Stratified QG runner execution or forcing/observer/output graph integration; those remain #297–#298.

Create the kernel from a shared scientific source and a caller-owned FFT engine. The optional setup-only matrix-backend factory defaults to the scalar reference backend; callers can supply a native matrix adapter. Preparation uses #357's full-FFT gather/embed service and four shared F/G projection/reconstruction operators. Coefficients remain canonical interleaved `[Nj,Nkl]`; physical arrays use MATLAB column-major `[Nx,Ny,Nz]`. Surface fields require `[Nx,Ny,1]`. No `Ap`/`Am` state or per-horizontal-mode matrix expansion is introduced.

The API provides raw QGPV and U/V/displacement projection, field reconstruction and first x/y/z derivatives, nonlinear PV advection, explicit beta-plane tendencies and exact linear Rossby evolution, spectral and spatial energy/enstrophy, and maximum horizontal speed. Fields include u/v, zero w, displacement, pressure height `pi`, pressure `p=rho0*g*pi`, streamfunction, QGPV, excess/total density, vertical vorticity and surface height/velocity. F-plane `evolveA0` is stationary regardless of reference time. Beta is an explicit argument to evolution and tendency methods; the geometry's planetary beta is available in `factors()` but is not silently enabled.

MATLAB's geostrophic mask excludes every horizontal-mean mode, including baroclinic means. Raw QGPV projection retains its mean as MATLAB does; reconstruction and quadratic diagnostics apply the geostrophic mask. Barotropic displacement and the barotropic deformation wavenumber are zero. The retained Fourier list carries the horizontal antialias selection; projection cannot generate omitted modes. Vertical truncation uses the authoritative matrices and exact j keys, including non-prefix subsets.

Spatial energy uses the stored modal quadrature. `totalEnstrophySpatiallyIntegrated` deliberately matches MATLAB's current diagnostic, which uses trapezoidal integration on z; it need not equal spectral enstrophy on a nonuniform grid. Density derivatives use the product rule with N2 and `dLnN2`; horizontal derivatives of total density differentiate the anomaly, avoiding cancellation against the horizontally uniform background.

A kernel retains the scientific owner and owns its prepared operators and mutable workspaces. Reuse it during time evolution; changed scientific geometry or basis requires a new source and preparation. Calls using mutable scratch reject overlapping execution. Distinct kernels provide independent workspaces. Input/output buffers must be disjoint, except exact in-place linear tendency/evolution; partial overlaps are rejected. Array views describe their full required extent, so callers must supply storage for those shapes. Failed setup leaves an existing kernel untouched; FFT and backend execution failures propagate without promising rollback of output already written.

`storage()` separates shared scientific ownership, prepared operators, workspace capacities, mode factors and numerical scratch. Application scratch is two `[Nj,Nkl]` complex arrays, one `[Nz,Nkl]` complex array and four physical real volumes; retained-horizontal internal workspace and backend scratch are counted separately. Shared-source bytes must not be multiplied by the number of kernels sharing that owner. These are capacity estimates, not RSS: allocator overhead, small object/string/control-block storage and vendor internals are not exact process-memory measurements. Provider/plan figures remain lower bounds.

`TestWVStratifiedQGKernel` tests ownership, bad shapes/pointers/aliases, failed FFT/backend setup, allocation-failure cleanup and zero prepared application allocations. `UnitTests/TestStratifiedQGCompiledKernel.m` compares independent MATLAB fields, factors, projections, derivatives, round trips, nonlinear and beta tendencies, linear evolution and diagnostics over two variable profiles, odd/even nonsquare grids, masks on/off, several modal resolutions and a non-prefix subset. Set `WV_QG_KERNEL_DUMP` to a built `WVStratifiedQGKernelDump`; `WV_QG_TEST_NATIVE=1` adds the native FFT provider when that executable was built with it. Otherwise the test builds its own temporary reference executable. Production MATLAB code is unchanged by #296.

The SQG kernel also provides vertical-diffusivity and linear/quadratic bottom-friction flux operations used by the #297 runtime. They preserve MATLAB's intermediate F/G projections and bottom quadrature normalization. `advectScalarWithAdvectionFields` differentiates a full three-dimensional tracer grid horizontally, then optionally projects its flux onto the retained horizontal set. `WVRetainedHorizontalOperator::spatialDerivative` reuses its full FFT workspace without restricting the derivative to the retained modes; the selected even-grid Nyquist derivative is zero. These prepared calls reuse existing scratch storage.

## Hydrostatic numerical kernel

`WaveVortexKernel/WVTransformHydrostaticKernel.hpp` implements the standalone variable-stratification kernel under internal contract `wave-vortex-hydrostatic-kernel-v1` (#299). It consumes the same immutable `WVStratifiedModalSource` as Stratified QG, with `transformClass` set to `WVTransformHydrostatic`. The runtime modal reader supplies this source from default MATLAB output without recomputing modes. The core depends on neither MATLAB nor NetCDF. Complete Hydrostatic model execution, forcing composition, observers and restart integration are provided by the [portable runtime](../PortableRuntime/README.md#hydrostatic-model-runtime) (#300); end-to-end qualification belongs to #301.

`create(source, engine, kernel, matrixBackendFactory)` prepares a retained horizontal transform and four shared F/G projection/reconstruction operators. The default matrix factory is scalar; Apple callers can pass `WVCreateAccelerateMatrixBackend`. Both reference FFT and native FFTW with scalar/Accelerate matrices are checked against MATLAB. The operators use the benchmark-selected full-FFT gather/embed and grouped dense-matrix services. Matrices are shared across horizontal modes rather than expanded per mode.

The public state uses interleaved `[Nj,Nkl]` Ap/Am/A0 amplitudes at `t0` and current time `t`. Reconstruction applies `exp(+i*Omega*(t-t0))` to Ap and its conjugate to Am; projection removes those phases. `evolveCoefficients` returns current-time amplitudes for the f-plane linear solution. Stored amplitudes have no additional linear tendency. Frequencies, energy weights and all projection/reconstruction factors are available through `factors()`.

The kernel provides:

- Raw F/G transforms, U/V/displacement projection and reconstruction of u/v/w, displacement, pressure height `pi`, pressure `p=rho0*g*pi`, geostrophic streamfunction/QGPV, excess/total density, three vorticity components and surface height/velocity.
- First x/y/z derivatives of those fields, except horizontal vorticity derivatives. Surface output uses `[Nx,Ny,1]`; other physical arrays use MATLAB column-major `[Nx,Ny,Nz]`. Density derivatives use N2 and `dLnN2` with the product rule.
- Full-flow, internal-wave, inertial, geostrophic and mean-density-anomaly component fields and modal/spatial energy. Total density includes the background only for the full flow. Spectral enstrophy is also available. Nonlinear exact APE/APV diagnostics are outside this contract.
- Full-grid horizontal differentiation and F-grid scalar advection support 3D tracers without truncating their vertical derivative to horizontal retained modes. Optional tracer antialiasing applies the horizontal projection, matching MATLAB.
- Unforced nonlinear hydrostatic advection, including `w*(eta_z + eta*dLnN2)` in the displacement tendency, projected back into reference-time amplitudes. Forcing composition and integrator/observer services are provided by the portable runtime.
- Explicit accepted-state constraints: remove inactive amplitudes, set inertial Am to conjugate Ap, and make mean-density A0 real. The mode list carries horizontal antialias selection; authoritative j keys and matrices carry vertical truncation, including non-prefix subsets. No second implicit truncation is applied.
- `differentiateVertical` for MATLAB F/G orders 1–4 and `integrateVertical` for first antiderivatives. These operate on every horizontal grid column, including frequencies omitted from the retained Fourier list. Repeated derivatives preserve MATLAB's intermediate vertical projections. Integration uses MATLAB's representable-mode convention: IntF removes the barotropic mode and vanishes at both boundaries; IntG fixes the bottom value to zero.

One kernel owns one reusable mutable workspace. Concurrent execution requires separate instances; overlapping scratch calls return an error. Public input/output arrays must be disjoint, except corresponding exact in-place linear evolution. Output coefficient families must be mutually disjoint. Views require caller-provided storage for their complete extents. Invalid metadata, unsupported enum values, nonfinite state and overlaps are rejected before output mutation. Failed construction preserves an existing kernel. Backend execution failures propagate without guaranteeing rollback of output already written. Raw transforms require valid real-field Hermitian means and do not silently repair arbitrary complex input.

With `S=Nj*Nkl`, `H=Nz*Nkl` and `R=Nx*Ny*Nz`, owned numerical scratch is `4S+2H` complex values and ten real volumes (six with the opt-in streamed schedule), plus one factor record per spectral mode. Raw vertical calculus batches physical columns through the prepared matrices without caching dense `Nz`-by-`Nz` derivative matrices. `storage()` separates shared scientific bytes, prepared objects, workspaces, factors and scratch. These capacity estimates exclude allocator/control-block overhead and some small string storage; vendor provider/plan figures are lower bounds, not RSS. Shared scientific bytes count once when sources are shared. Prepared application execution allocates zero memory in the qualified paths, retains constant reported storage, and releases scientific ownership at destruction.

Build `TestWVHydrostaticKernel` and `WVHydrostaticKernelDump` from `PortableRuntime`. CTest `hydrostatic-kernel` covers invalid shapes/pointers/enums/aliases/time, exact in-place evolution, setup/FFT/backend allocation-failure sweeps and ownership. `UnitTests/TestHydrostaticCompiledKernel.m` compares MATLAB factors, fields and components, transforms, vertical calculus, energy/enstrophy, phases, constraints, nonlinear flux and a four-step RK4 trajectory over two profiles, odd/even grids, antialiasing on/off, several Nz/Nj combinations and a non-prefix southern-latitude case. It checks 13 cases per provider with tolerance `2e-10*max(abs(expected)) + 1e-18` for each quantity. Set `WV_HYDRO_KERNEL_DUMP` to an existing probe; `WV_HYDRO_TEST_NATIVE=1` tests reference, native/scalar and native/Accelerate. Without an executable override, the test builds a temporary reference probe. `.github/workflows/hydrostatic-kernel.yml` repeats reference parity and contracts on Linux in release and ASan/UBSan configurations independently of optional Full CI.

## Boussinesq numerical kernel

`WaveVortexKernel/WVTransformBoussinesqKernel.hpp` implements `wave-vortex-boussinesq-kernel-v1` (#302). It consumes an immutable Boussinesq `WVStratifiedModalSource` decoded from default v4 MATLAB output. Kernel execution requires no MATLAB, NetCDF I/O or eigenmode solve. Complete-model forcing, observers, integrators and restart dispatch are provided by #303; longer end-to-end readiness qualification remains #304.

The compact state is interleaved `[Nj,Nkl]` Ap/Am/A0 at reference time `t0`, with current time `t`. Wave matrices retain the exact persisted `K2unique`/`iK2unique` grouping, including discontiguous columns, and are prepared through the existing grouped matrix service. Each group has its own immutable matrix identity. The scalar and Accelerate matrix factories and reference/native FFT providers use the same numerical API. The shared geostrophic F/G basis and wave Fw/Gw basis remain distinct; inertial velocities use the zero-wavenumber wave F basis.

The kernel exposes three- and four-field projection, u/v/w/displacement reconstruction, pressure, density, streamfunction, QGPV, vorticity and surface fields; component fields and modal/spatial energy; spectral enstrophy; phases, accepted-state constraints and unforced four-field nonlinear advection. Spatial energy includes vertical kinetic energy. The displacement tendency includes `w*eta*dLnN2`. Wave frequencies and factors use persisted `h_pm`, while balanced factors retain `h_0`. Projection implements the MATLAB `Ddelta`, vertical-velocity weight and persisted `QGwg` cross-projection.

Raw transforms distinguish `F`, `G`, `Fw` and `Gw`. Vertical calculus accepts the shared `F`/`G` basis, matching MATLAB `diffZF`/`diffZG` orders 1–4 and first antiderivatives on every physical horizontal column. Field z derivatives apply that same finite-resolution calculus after reconstruction, including for wave fields. They do not replace MATLAB's operation with analytical wave-mode derivatives. Horizontal field derivatives preserve the selected compact Fourier map; the separate full-grid horizontal derivative service preserves all resolved columns. Nonlinear exact APE/APV diagnostics remain outside the kernel contract.

One instance owns reusable mutable workspaces and retains its scientific source. Public arrays use the Hydrostatic kernel's shape, disjointness and error conventions; exact corresponding in-place coefficient evolution is supported. With `S=Nj*Nkl`, `H=Nz*Nkl`, and `R=Nx*Ny*Nz`, numerical scratch is `7S+5H` complex values and eleven real volumes. Eleven prepared vertical operators retain shared/grouped matrix products, and the horizontal operator owns its FFT workspace.
